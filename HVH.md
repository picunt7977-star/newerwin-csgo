# ECLIPSE — хвх для CS:GO legacy (Linux)

Основа — [Osiris](https://github.com/danielkrupinski/Osiris), ветка `csgo` (MIT). Поверх добавлено:
рейджбот, автоволл, DT, антиаимы с десинком, меню в стиле Neverlose.

## Граница

- Чит работает **только** если игра запущена с `-insecure` (`Source/InsecureGate.h`).
  С этим флагом движок сам не пускает на VAC-серверы — значит, только insecure/хвх-серверы
  и локальная игра.
- Никакого обхода или сокрытия от VAC. Репортбот вырезан.

## Сборка и запуск

```
./csgo-hvh.sh            # собрать и показать параметры запуска
```

Параметры запуска в Steam (CS:GO legacy):

```
SDL_VIDEODRIVER=x11 LD_PRELOAD="$LD_PRELOAD:/home/alex/csgo-hvh/build/Source/libOsiris.so" %command% -insecure
```

`SDL_VIDEODRIVER=x11` обязателен: в Hyprland задано `wayland,x11,windows` (синтаксис SDL3),
встроенная в игру SDL2 его не понимает и игра падает на старте — даже без чита.

Меню — `Insert`. Чит поднимается через ~5 секунд после главного меню игры.

## Резольвер по слоям анимации

Из `DT_CSPlayer` сервер вырезает `m_flPoseParameter` (там лежал бы `body_yaw` — готовый ответ),
но **не** вырезает `m_AnimOverlay`: 13 слоёв анимации игрока приходят по сети такими, какими их
посчитал сервер — то есть из **настоящего** угла ног врага. На этом и построен резольвер:

1. `FRAME_NET_UPDATE_POSTDATAUPDATE_START` — единственный момент, когда сетевые слои ещё не
   перезатёрла клиентская анимация. Снимаем их (`Resolver.cpp: onNetUpdate`).
2. Берём `animstate` врага, подставляем угол ног-кандидат (сетка ±максимальный десинк, `m_flLowerBodyYawTarget`,
   наш прошлый ответ, крайние углы от прошлого взгляда — на случай джиттера) и зовём ту же функцию движка,
   что зовёт сам клиент: `CCSGOPlayerAnimState::Update`.
3. Сравниваем полученные слои с сетевыми. Ошибку по каждому полю (`m_flWeight`, `m_flCycle`,
   `m_flPlaybackRate`, `m_nSequence`) делим на разброс этого поля между кандидатами — так в счёт идут
   только те слои, которые вообще зависят от угла ног (доворот ног, стрейф, lean), а не шум и кванты.
4. Побеждает кандидат с минимальной ошибкой; отдаём **угол ног после обновления** — движок сам
   обрезал его по максимальному десинку, значит он физически возможен. Уверенность — отрыв от
   второго кандидата с заметно другим углом.
5. Состояние после лучшего кандидата остаётся «тенью»: с него считается следующее обновление,
   чтобы наша история анимации шла в ногу с серверной.
6. Поверх угла — режимы коррекции (`слои` / `зеркало` / `половина`) со счётом по попаданиям и
   промахам: если слои врут (дефенсив, лютый джиттер), счёт сам уводит на зеркальный угол.

Рейджбот собирает скелет записи ровно под этот угол (`Ragebot.cpp: rebuildAtYaw`), а крайние углы
(`±maxDesync`) оставляет для безопасных точек. Если слои молчат (враг стоит, ноги не крутятся) или
сервер их не шлёт — остаётся старый путь: фристенд-догадка плюс перебор стороны по промахам.

Что разобрано из `client_client.so` (клиент 13546, linux64) и где это в коде:

| Что | Значение | Где |
|---|---|---|
| `CCSGOPlayerAnimState::Update(this, bool force, float yaw, float pitch)` | `0xf45560` | паттерн в `LinuxClientPatternFinder` |
| `m_pPlayerAnimState` в `C_CSPlayer` | `+0xa250` | берётся из байтов вызова Update |
| размер animstate | `0x3b8` | `CSGO/AnimState.h` |
| `m_flEyeYaw` / `m_flPitch` / `m_flFootYaw` | `0x8c` / `0x90` / `0x94` | там же |
| `m_flLastUpdateTime` / кадр / дельта | `0x80` / `0x84` / `0x88` | там же |
| `m_flDuckAmount`, доли скорости, `m_flMaxBodyYawDegrees` | `0xb8`, `0x10c`/`0x110`, `0x3a8` | там же (формула максимального десинка) |
| `CAnimationLayer` | шаг `0x48`, `m_nOrder 0x18` … `m_flCycle 0x30` | `CSGO/AnimationLayer.h` |
| `m_AnimOverlay` | офсет из netvar игры | `Entity::animOverlayVector` |

Проверки на всякий случай: офсет animstate берётся только из разобранного кода (не нашёлся — всё,
что читает animstate, выключается), поля проверяются на правдоподобие, `animstate->player` должен
совпасть с игроком, а сетевые слои — пройти проверку на вменяемость. При любом несовпадении в консоль
летит `[ECLIPSE]`-сообщение и резольвер откатывается на геометрию.

В консоли при первом обновлении печатается строка с найденными офсетами и тем, приходят ли сетевые
слои; на каждый промах по вине резольвера — его дельта, уверенность, ошибка и число сигналов.
Под прицелом индикатор `R +12°  64%` (угол ног относительно взгляда и уверенность).

## Известные ограничения

- Хитшанс считает только `inaccuracy` оружия, базовый `spread` не учитывается — хитшанс слегка завышен.
- Резольвер по слоям разобран под конкретную сборку клиента (13546): на другой сборке он сам себя
  выключит и останется перебор стороны по промахам.
- Пока враг стоит и ноги не крутятся, слои про угол ног ничего не говорят — там работает фристенд-догадка.
- DT зависит от `sv_maxusrcmdprocessticks` сервера (по умолчанию 16 — работает).
